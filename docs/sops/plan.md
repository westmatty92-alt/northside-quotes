# SOP plan for Northside quote requests

Written in the design phase (step DOC0, 2026-11-19) from the PRD v1.1, design specs, user flows, architecture, security model, integration contract and the account-setup packet. This is a plan. Nothing here is built yet, and no SOP exists yet. Every row is written in the verify phase (DOC1) from evidence, and a row changes or drops if the build changes or cuts the thing it covers.

Kinds: 1 company · 2 operator · 3 install/redeploy · 4 agent (kit, index only) · 5 client staff. Homes use `docs/sops/<kind folder>/<procedure>.md` (folders: `operator/`, `client-staff/`). Kind 2 files publish to the Baseleap SOP Hub in Notion only when the DOC1 step says so; kind 5 never goes to the Baseleap hub.

## Not documented, and why
- **Homeowner "Request a quote" form and confirmation (SCR-01, SCR-02).** The screens are the instructions, and the homeowner is not trained. The one gap, that the reference number is the only receipt, is said on SCR-02 itself.
- **Inbox extras: status filter, search, Show more, full-size photo viewer, "Last updated by".** Obvious on screen. The ones that can fail (changed by someone else, Photo unavailable) are covered in "If it goes wrong" of the inbox SOP.
- **Sign-up, password reset, magic links, in-app user management.** None exist in v1 (NG-4). The SOPs say so where a person might look for them.
- **Account setup packet** (GitHub, Supabase, Vercel, by Matthew). `docs/ops/account-setup.md` already is the procedure, owned by devops. The hub links to it and docs does not write a second copy. Its Part 7 (production) feeds the release and rotation SOPs by link.
- **Pipeline drills, scanner install, QA triggering the GHL job by hand on staging.** Test and pipeline practice owned by devops and QA (`docs/ops/**`, `docs/test-plan.md`). They are evidence for the SOPs above, not SOPs for an operator.
- **Ending the rehearsal** (delete the two Supabase projects and the Vercel project, revoke tokens, remove repo access). Written once in account-setup "Afterwards". A one-time wrap-up of throwaway accounts, not a repeatable procedure.
- **Waking a paused Supabase project** (Free projects pause after a week idle). Rehearsal staging only, one dashboard click. It becomes one line in the release SOP's "If it goes wrong" if the drills show it. A real client moves to a paid plan first (A1 decisions D-A1-1 and D-A1-2).
- **Agent SOPs (kind 4) and install/redeploy guides (kind 3).** This build changes no agent behaviour and installs no agent team. The kit is untouched.
- **Company SOPs (kind 1).** Nothing in this build creates a company-wide procedure.

## Open questions (for Gate 2)
1. **Where do the client staff SOPs live?** Kind 5 goes in "the client's own docs location named in the build plan", and no plan names one. Northside Plumbing (TEST) is a fake client with no docs home. Suggestion: keep the three kind-5 files in this repo under `docs/sops/client-staff/` for the rehearsal, with no Notion copy. Matthew confirms, or names a place.
2. **How does a staff member get the first password, and who resets a forgotten one?** No email is sent (NG-1, NG-4), so there is no reset email. The security model says Baseleap creates the accounts with long generated passwords, but no document says how the password reaches the owner, or what Baseleap does when someone forgets one. Without an answer, the add-account SOP can only carry an unverified step for the hand-over, and a "reset a password" SOP is missing. Needs a decision from Matthew; a reset procedure would be a new row.
3. **Is there a manual retry for a failed stage tag?** The design has "Retry copy" only (US-014, Could). A failed stage tag shows no button, and the integration contract has no stage-tag retry route. The staff SOP would say "change the status again to start a new push, or tell Baseleap". Is that what Matthew intends? Also, if US-014 is cut, a failed copy has no retry at all, so the operator SOP must say how Baseleap re-arms the job. The architect and the integration step should confirm the repair route.
4. **Production release credentials conflict.** `docs/ops/account-setup.md` Part 7 still lists a Supabase release access token (`SUPABASE_ACCESS_TOKEN`, 28-day expiry) for the GitHub `production` environment. PLAN.md records Matthew's Nov 18 rule: no Supabase personal access token anywhere, and release migrations use the production database connection string stored only in the GitHub `production` environment. The release, rollback and rotation SOPs cannot be written until devops and Matthew say which one is true. Docs will follow the shipped workflow, names only.
5. **Is rollback drilled, including a migration?** The A1 report says each migration has a rollback block, but nothing says the pipeline drills run a rollback or a down-migration. If the drills skip it, the rollback SOP is written with the database part marked unverified. Ask devops to include one rollback drill, or accept the gap at Gate 3.
6. **Secret rotation has no drill.** `APP_SIGNING_SECRET` is new and not yet in account-setup. Changing it should invalidate open form tokens (a homeowner mid-form gets a refreshed token) and reset the rate-limit and sign-in counters. Changing `CRON_SECRET` has to match what Vercel sends on cron calls. These effects come from the security model and architecture, not from a run. Ask devops to rotate one secret on staging so the SOP has evidence, or accept unverified steps.
7. **Who reads the metrics, and how?** The PRD asks for a 14-day baseline of median hours to first quote and a 30-day guardrail check. The metrics spec stores events in the `events` table and defines the numbers, but no screen shows them and nobody owns the query. This is not planned as an SOP. If Matthew wants one ("read the weekly metrics"), it needs a saved query or script, which is a build change.
8. **GHL facts that can only be settled live** (OQ-15 tag auto-creation, the API version header, duplicate search right after a create). The operator recovery SOP will carry unverified steps for these unless the integration step's first live test on the test sub-account settles them before DOC1.
