**What the script does**
- Parses by position, never `new URL()`: scheme up to `://`; the host part is everything after the **last** `@`, so a password holding `@ / ? #` cannot move the host, port or database; user and password are split at the first `:` of what is left. Nothing parsed from the value is ever printed; the facts object holds booleans and fixed words only, and the port is printed only when it is 1 to 5 digits (otherwise "invalid").
- Prints: leading or trailing whitespace; newline anywhere; whitespace inside; scheme (`postgres`, `postgresql`, `other`, `none`); host class (`*.pooler.supabase.com`, `db.*.supabase.co (DIRECT)`, `other`; a lookalike such as `x.pooler.supabase.com.evil.example` is "other"); port; password field present; database name is `postgres`. **Additions beyond your list, all yes/no or a fixed word, none echo a value:** password is still `[YOUR-PASSWORD]` (the most likely paste mistake); password has characters needing percent-encoding (`@ / ? # [ ] space`, lone `%`; `:` is allowed); user is `postgres.<SUPABASE_STAGING_REF>` (a plain `postgres` user on a pooler gives "Tenant or user not found"); pooler region is `ca-central-1`; `sslmode` (only a known word, else "invalid").
- Probe: `psql "$SUPABASE_STAGING_DB_URL" -w -X -v ON_ERROR_STOP=1 -qAt -c 'select 1'` (`-w` so it can never wait for a password, `-X` ignores any psqlrc, `PGCONNECT_TIMEOUT=15`, 45 s cap). Output is captured by Node, matched against patterns, then dropped; **nothing from stderr is ever printed**, including for the "other" class (libpq puts host, IP and sometimes the user in its messages). Classes: could not translate host name, network unreachable (IPv6?), password authentication failed, pooler "Tenant or user not found", no password supplied, too many connections, connection refused, timed out, SSL, invalid connection address, database does not exist, psql missing, other.
- Failure: exit 1 with `::error::` first line (the class's plain message, ending "Fix: docs/runbook.md, section "Staging database address for CI"."), then one `::error::` line per extra problem the facts show (whitespace, wrong port, placeholder, encoding, wrong user, wrong region, direct host, missing password, wrong scheme, db name). If the probe connects, exit 0, and any such problem is only a `::warning::`. An empty value fails before the probe.
- Special characters: the self-test has 8 passwords (`@ / ? # [ ] space %`, all together) that must still give the right host class, port, database and user check, and be flagged; an already percent-encoded one must not be flagged.
- Leak test inside the self-test: 6 hostile values (sentinel user, password, host, database; trailing newline; `@ ? # [ ] %` inside the password; the sentinel as port and as `sslmode`; no scheme; no database) times 4 psql stderrs that contain the sentinels times exit 0 and 2 = 48 combinations; the full output must contain none of the sentinels nor the whole value.
